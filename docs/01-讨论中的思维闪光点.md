# 讨论中的思维闪光点

> 这份文档记录立项讨论过程中出现的关键判断，是"为什么这么设计"的原始依据。跟 [00-项目定位与迭代路径.md](00-项目定位与迭代路径.md) 的关系是：00 记结论，这里记推导过程和判断标准，方便以后回头看忘了"当初为什么这么定"的时候查。
> 最后更新：2026-08-15

## 1. 可靠的 goal loop 不止要求度量"客观"，更要求度量"连续、带方向"

判断一个 goal loop 好不好用，光问"这个度量客不客观"不够，真正决定改进效率的是**度量结果有没有直接告诉下一步该往哪个方向动**：

- 梯度下降式的度量（比如训练里的 loss）：既客观又连续，数值变化本身就是方向盘。
- 语义检查式的度量（比如判断正文有没有踩中某条约束）：客观但离散无方向，只能回答"对不对"，回答不了"往哪个方向改"，所以必须在度量之上再加一层"诊断"去人工制造方向。

**对读码机的具体指导**：这也是为什么"为什么类"题目要单独设计判分逻辑（不能只判"对/错"，还要判"提到了哪些关键论点、漏了哪些"）——一个只会输出对/错的评测集，没法指导 Agent 具体该往哪个方向改进，跟只有二元度量的 goal loop 是同一个局限。

来源：goal loop 接入自动剧本生成机后，跟 GCG 项目类比讨论时得出的结论（另存于自动剧本生成机 docs/00 第 18 条）。

## 2. "人定义目标"和"人介入循环"是两件事，不要混为一谈

一个 loop 要不要有人时刻盯着（human-gated）还是完全自主运行（autonomous），问的是**循环运行过程中有没有人做检查点**，不是问"目标是不是人定的"。人一次性把目标定清楚（写考卷、定测试用例、选目标字符串），这是"设置"，不是"介入循环"——循环本身一旦开始运行，中途没有人再插手，才算真正的自主循环。

**对读码机的具体指导**：出考卷这件事本身要不要人工介入，跟"读码机读代码这个过程要不要人工介入"是两个独立的问题，前者当然需要人（现在这份考卷就是人写的），后者才是评判读码机自主程度的地方。不要因为出考卷需要人，就觉得整个系统"不够自主"。

## 3. "变强"有两种完全不同的时间尺度，效果不互相传递

- **跨版本迭代**：拿评测集测一批 → 发现某类问题答错 → 改进系统设计（换个记笔记方式、换个 context 策略）→ 重新测。这种"变强"是永久的，换到新代码库依然生效。
- **单次会话内的积累**：读得越多，关于**这一个代码库**的笔记越多，回答关于这个代码库的问题会越准。但这不是系统本身变聪明了，只是针对这一个代码库的信息变多了——换一个全新的代码库，这些积累全部归零（除非专门设计成按代码库把笔记落盘持久化）。

**对读码机的具体指导**：不要把"它现在很懂 `自动剧本生成机` 了"误当成"读码机整体变强了"。第 1 种变强靠考卷驱动的迭代来实现，第 2 种只是给单次任务攒素材，两者不能互相替代，评估进展时要分开看。

## 4. Eval 集和 Agent 机制，"通用不通用"这件事要分开看

Agent 本身的机制（怎么用工具翻文件、怎么管理读过的内容）从第一天就该设计成通用的，不该为某一个代码库单独定制——如果只在 `自动剧本生成机` 上好用，换个代码库就要重新设计，说明机制本身没搭对。真正天生不通用、每个代码库都要重新来一份的，只有考卷本身。

**对读码机的具体指导**：评估"这个系统做得好不好"，要分别问"机制通用吗"和"这份考卷覆盖得够吗"，混着问容易把"考卷需要扩充"误判成"整个系统设计错了"，或者反过来把"机制有缺陷"误判成"只是还没出够题"。

## 5. 先验证考卷本身，再动手搭系统——顺序不能倒

代码类知识的一个特殊之处：标准答案不依赖 Agent 存不存在（出题人自己就懂这个代码库，可以在 Agent 写出来之前就先定好标准答案），这点跟评测创作类内容不一样（创作评测往往需要先看到真实产出才知道该测什么维度）。

但即便标准答案能提前定，**考卷本身有没有歧义、判分标准写不写得清楚，还是要先用一个现成的、什么都没优化过的 Agent 去试跑一遍才知道**——这是"第 0 步"存在的原因：用最小成本（不写一行 Agent 代码）去排除"考卷本身有问题"这种情况，避免后面在一份有缺陷的考卷上反复调 Agent、却怎么都调不出好结果，最后才发现是题目本身出得不好。

## 6. 复杂机制（RAG/数据库）要等真实瓶颈出现再上，不要预判

想到"读码机应该有个知识库"是一个正确的直觉——但**在连最简单的"记一个文本文件"有没有用都没验证过的阶段就想上 RAG/SQL，是没有真实案例就开始设计详尽方案**，跟"先跑再迭代"的原则正好相反。

排查顺序应该是：先上最土的纯文本笔记 → 真实观察到笔记本身也大到读不过来了，或者需要按关键词/语义去查笔记里的某一段 → 这时候才是 RAG 真正该登场的时机，因为这时候有具体证据支撑这个决定，不是凭直觉预判会用得上。
