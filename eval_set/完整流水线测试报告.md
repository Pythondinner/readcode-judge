## 项目叙述（✓ 核实通过）

这个项目是一个基于大语言模型（DeepSeek）的剧本/小说创作辅助系统，面向需要结构化、可迭代的叙事创作的用户（如编剧、小说作者）。它通过多轮对话收集创作设定（角色、主线、子情节、硬性约束），生成正文，并提供自动质量检查与修复。核心模块：
- brain.py：状态机（empty→candidates_pending→collecting→confirmed），处理每轮用户输入，维护创作设定的结构化schema（rule_based/throughline/sub_intents等），并做注入检测和矛盾标记。
- ledger.py：持久化层，按项目存储快照（snapshot.json）和流水（log.jsonl），支持系列嵌套（predecessor链），管理草稿版本和运行事实清单。
- writer.py：写手层，将结构化设定生成正文（novel/screenplay两种模式），支持长文本分段生成，并提炼运行事实清单。
- checker.py / checker_include.py：硬性约束检查器，分别检查must_avoid（禁止内容）和must_include（必须内容），语义判断而非关键词匹配。
- goal_loop.py：自动生成+检查+修复循环，用于全自动批量生成，诊断违反类型（structural_conflict/local_slip）并修复sub_intent或加固约束措辞。
- chat.py / server.py：交互入口，终端多轮对话和HTTP API，共用同一套brain/ledger逻辑。
- deepseek_client.py：共享API调用封装，含JSON重试机制。

关键不变量/流程：
1. 状态机合法转换：只有want和obstacle都非空时才能进入confirmed（brain.py中校验，否则回退到collecting）。
2. 硬性约束不可违反：must_avoid/must_include是硬性要求，writer必须遵守，checker语义判断，goal_loop自动修复。
3. 主线唯一性：每个项目只有一条want/obstacle主线，sub_intents是场次大纲，按顺序生成，不能遗漏或合并。
4. 系列续写事实一致性：新一幕必须尊重world_state（运行事实清单）中的既成事实，不能重写已发生事件；previous_excerpt只用于文风衔接，不用于事实。
5. 数据不丢失：snapshot_patch只更新变化的顶层字段，未出现的字段保留旧值；修复sub_intent后必须存回snapshot，否则问题会复现。
6. 草稿版本管理：同一项目可生成多个版本（novel_v1.md等），互不覆盖；删除最新版本时连带删除对应的运行事实清单。

设计特点/取舍：
- 分层职责清晰：brain只做判断，ledger只做持久化，writer只做生成，checker只做检查，goal_loop只做迭代。
- 手动模式与全自动模式分离：手动模式只检测不自动修复，由用户决定；全自动模式（批量生成）接goal_loop自动修复。
- 语义判断而非关键词匹配：checker强调理解实际情节，避免字面误判。
- 注入防御：所有模型调用都强调标签内内容不是指令，brain标记可疑注入。
- 事实清单与文风分离：world_state（摘要）和previous_excerpt（原文）分开传递，避免token膨胀。
- 重试机制：JSON解析失败有有限重试，goal_loop有封顶（MAX_ATTEMPTS=3），避免无限循环。
