### 第1轮

## 跨函数模式归纳

### 静默覆盖与持久化副作用

**支撑证据：** writer.py::write_and_save_one、goal_loop.py::write_and_save_one_with_check、ledger.py::save_draft

多个函数在写入或更新数据时，倾向于静默覆盖已有内容而不进行显式提示或校验。例如，write_and_save_one 无条件保存草稿并更新 generated_from，即使项目未确认；write_and_save_one_with_check 在 cap_reached 时仍保存草稿；save_draft 生成新版本号时可能因脏文件名导致版本号不一致。这些行为可能导致调用方误以为操作成功或数据一致，实际却产生了意外覆盖或数据不一致。

### 隐式文件系统迁移与路径变更

**支撑证据：** ledger.py::_migrate_chain_to_series、server.py::continue_from、chat.py::maybe_link_predecessor

多个函数在创建承接或续写时，会触发磁盘目录结构的物理迁移（如 shutil.move 或 os.rename），改变已有项目的存储路径。调用方若未预期这些副作用，可能因路径变化导致缓存失效或误操作。例如，_migrate_chain_to_series 即使对独立项目也会改变其磁盘布局；continue_from 和 maybe_link_predecessor 在成功创建新项目时也会迁移整条链。

### 需要两步确认的流程

**支撑证据：** server.py::write_draft、server.py::continue_from

多个 HTTP 接口在存在冲突或已有数据时，不直接失败或覆盖，而是返回 needs_confirmation 标志，要求调用方进行二次确认。例如，write_draft 在已有草稿且未带 force 时返回 needs_confirmation；continue_from 在 predecessor 已有后继且未带 force 时也返回 needs_confirmation。调用方若未检查该标志，可能误以为操作已成功，实际未执行任何写入。

### 全局环境与状态修改

**支撑证据：** chat.py::main、chat.py::load_env、server.py::load_env

多个函数会修改进程级全局状态，如 stdout 编码和 os.environ。main 无条件 reconfigure stdout 并调用 load_env；load_env 使用 setdefault 写入环境变量，但不会覆盖已存在的值。这些副作用可能影响调用方在同一进程中的其他操作，且不易察觉。

### API 调用次数与成本隐藏

**支撑证据：** deepseek_client.py::call、goal_loop.py::check_and_report

多个函数在内部会发起多次 LLM API 调用，但调用方只看到一次函数调用，容易低估延迟和费用。deepseek_client.call 在 json_mode 下可能重试最多 3 次；check_and_report 为每条违反的 must_avoid 条目调用一次 diagnose，导致多次 API 调用。调用方若未意识到这一点，可能在批量处理时产生意外的高成本。

## 优先处理清单

1. **goal_loop.py :: write_and_save_one_with_check** —— 该函数在 status 为 cap_reached 时仍无条件保存草稿，导致有缺陷的正文被持久化，且 sub_intents 修复与草稿保存不同步，可能造成数据不一致。这是高风险副作用，应优先处理。
2. **writer.py :: write_and_save_one** —— 该函数不校验项目状态，可能对未确认的幕次生成并保存草稿，且静默覆盖 generated_from。调用方若误用，会生成不应落盘的草稿，影响后续流程。
3. **ledger.py :: _migrate_chain_to_series** —— 该函数会实际移动磁盘文件夹，即使对独立项目也会改变其路径，副作用隐蔽且影响磁盘布局。调用方若误用，可能导致路径失效或数据错乱。
4. **server.py :: continue_from** —— 该接口在需要确认时返回 200 而非错误码，调用方易忽略 needs_confirmation 字段而误以为创建成功，且成功时会触发整条链的物理迁移，副作用大。
5. **server.py :: write_draft** —— 该接口在已有草稿且未带 force 时返回 needs_confirmation，不生成内容，调用方若未实现两步确认会误以为成功，且可能意外覆盖旧草稿。
6. **deepseek_client.py :: call** —— json_mode 下可能重试多次，产生额外 API 调用和费用，且缺 key 时抛 SystemExit 而非 ApiCallError，调用方可能未捕获导致进程终止。
7. **chat.py :: main** —— 该函数无条件修改全局 stdout 编码和环境变量，且可能通过 offer_to_write 写入文件，调用方若复用会污染进程状态。
8. **goal_loop.py :: check_and_report** —— 该函数为每条违反条目发起独立 LLM 调用，可能产生大量 API 请求，成本高，调用方应知晓并控制调用频率。

### 静默覆盖与持久化副作用

**支撑证据：** writer.py::write_and_save_one、goal_loop.py::write_and_save_one_with_check、ledger.py::save_draft、ledger.py::delete_draft

多个函数在生成或删除草稿时，会静默地覆盖或删除相关数据，且不向调用方明确提示。例如，write_and_save_one 无条件保存草稿并更新 generated_from，即使生成可能不完整；write_and_save_one_with_check 在 cap_reached 时仍保存草稿；save_draft 自动递增版本号，可能覆盖同名文件；delete_draft 删除最新版本时连带删除 state 文件。这些副作用在函数名或 docstring 中不明显，调用方容易忽略。

### 全局状态修改

**支撑证据：** chat.py::load_env、server.py::load_env、chat.py::main

多个函数会修改进程级全局状态：load_env 使用 os.environ.setdefault 修改环境变量，main 调用 sys.stdout.reconfigure 改变全局 stdout 编码。这些修改影响整个进程，调用方若在复用环境中使用，可能产生意外副作用。

### 磁盘迁移与路径变更

**支撑证据：** ledger.py::_migrate_chain_to_series、server.py::continue_from、chat.py::maybe_link_predecessor

多个函数在创建承接或续写时，会触发磁盘目录迁移（shutil.move/os.rename），改变已有项目的物理路径。例如 _migrate_chain_to_series 将扁平项目迁移为嵌套结构，continue_from 和 maybe_link_predecessor 调用该迁移。调用方若缓存了旧路径，会失效。

### API 调用隐藏成本

**支撑证据：** deepseek_client.py::call、goal_loop.py::check_and_report、writer.py::write_long_script

多个函数在内部发起 LLM API 调用，但调用方可能误以为它们是本地操作。deepseek_client.call 在 json_mode 下可能重试最多3次，check_and_report 对每条违反项调用 diagnose（一次 API），write_long_script 对每段调用 write_script 和 extract_world_state。这些调用产生延迟和费用，调用方应意识到。

### 状态校验缺失或静默回退

**支撑证据：** writer.py::write_and_save_one、brain.py::process_turn、server.py::write_draft

多个函数在状态校验上存在缺失或静默回退：write_and_save_one 不校验项目状态是否为 confirmed，直接生成并保存；process_turn 在 next_state 非法或 confirmed 校验失败时静默回退为 collecting；write_draft 在项目未确认时返回 400，但调用方可能忽略。这些行为可能导致生成不合适的草稿或状态转移失败。

## 优先处理清单

1. **writer.py :: write_and_save_one** —— 该函数不校验项目状态，可能对未确认的幕次生成并持久化草稿，且静默覆盖 generated_from，副作用严重且隐蔽。
2. **goal_loop.py :: write_and_save_one_with_check** —— 即使生成未通过检查（cap_reached）也无条件保存草稿，导致有缺陷的草稿被持久化，调用方可能误以为未通过就不会落盘。
3. **ledger.py :: _migrate_chain_to_series** —— 该函数会实际移动磁盘文件夹，即使对独立项目调用也会改变其路径，副作用大且不易察觉，调用方可能意外改动文件系统布局。
4. **server.py :: continue_from** —— 即使 force 为假且 predecessor 已有后继，也返回 200 而非错误码，调用方必须检查 needs_confirmation 字段，否则误以为创建成功；且成功创建会触发整条链的物理迁移。
5. **deepseek_client.py :: call** —— json_mode 下可能实际发送最多3次请求，调用方只看到一次调用但账单和延迟是多次的；缺 API key 时抛 SystemExit，若只捕获 ApiCallError 会漏掉。
