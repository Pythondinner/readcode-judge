## 项目叙述（✓ 核实通过）

这是一个基于 DeepSeek 大模型、以"对话式共创剧本"为核心的项目，面向想写小说/剧本但不想从零起稿的用户（或作为创作辅助工具）。用户通过多轮自然语言对话，由系统逐步把零散想法整理成结构化的剧本设定（角色、主线 want/obstacle、场次大纲、硬性约束），再自动生成正文，并支持系列续写、自动质量检查与修复。

主要模块与职责边界：
- brain.py：交互状态机（empty→candidates_pending→collecting→confirmed），每轮把用户输入合并进 snapshot，负责 want/obstacle 推断、矛盾检测、注入防御；状态转移由模型提议、代码层校验兜底（如 confirmed 必须 want/obstacle 非空）。
- ledger.py：持久化层，按项目/系列分文件夹存 snapshot.json、log.jsonl、drafts/<mode>_v<N>.md 和 <mode>_state.md（运行事实清单）；负责系列嵌套迁移、承接（create_continuation）、草稿版本管理、事实清单收集。
- writer.py：写手层，把 snapshot 的 schema 映射成正文（novel/screenplay 两种格式），支持长文分段（write_long_script）、跨幕文风衔接（previous_excerpt）与事实一致性（world_state）。
- checker.py / checker_include.py：硬性约束检查器，分别检查 must_avoid 是否被违反、must_include 是否被满足，语义判断而非关键词匹配。
- goal_loop.py：自动生成+检查+修复循环（write_with_check），诊断违反类型（structural_conflict/local_slip）、修复冲突的 sub_intent 或加固约束措辞、重试封顶；手动模式只诊断不自动改（check_and_report）。
- chat.py / server.py：两个入口，chat.py 是终端多轮对话，server.py 是 Flask HTTP 后端，两者共用同一套 brain/ledger 逻辑。
- deepseek_client.py：共享的 API 调用封装，含 JSON 格式重试、max_tokens 截断检测。

关键不变量/流程（用于对照检查函数行为）：
1. 状态机合法转移：confirmed 必须 want 和 obstacle 都非空（brain.process_turn 里校验，否则退回 collecting）；状态只能按 empty→candidates_pending/collecting→confirmed 推进，不能非法跳转。
2. 硬约束不可违反：must_avoid 绝不能出现（语义等价也算违反），must_include 必须真正体现；checker 用语义判断，不是关键词匹配。
3. 修复不污染原始数据：write_with_check 在 snapshot 的内存拷贝上修复，不直接改调用方传入的 snapshot；是否存回 ledger 由调用方决定。
4. previous_excerpt 是跨幕文风锚点，重试时保持不变，绝不能被替换成本幕失败的重试草稿（goal_loop 注释明确强调）。
5. 修复后的 sub_intents 必须存回 snapshot（否则下次生成仍用旧冲突大纲，问题复现）；但重试中"加固措辞"的 must_avoid/must_include 不存回（那是只对本轮重试有意义的临时提示，存成永久措辞会误导后续生成）。
6. 系列续写必须按顺序：已有正文的跳过、遇到未收尾（非 confirmed）的幕次就停（write_missing_acts_in_series）；承接只能从 confirmed 的项目（create_continuation 抛 ContinuationError）。
7. 事实一致性：新一幕开场角色位置/状态必须与 world_state 清单一致，已发生的不可逆事件不能被忽略或重写（writer CORE_RULES 明确 world_state 优先级高于文风参考）。
8. 草稿版本不覆盖：save_draft 用递增版本号，同一项目可反复生成不同模式/版本；删除最新版本时连带删除对应 state 文件（delete_draft）。
9. 生成失败无副作用：模型调用失败（ApiCallError）时上层 snapshot/草稿不被写脏，调用方提示重试。
10. 删除/重新生成需两步确认：server.py 中删除项目、重新生成已有正文都必须先返回依赖信息（successors/dependents），用户确认后带 force=true 才执行。

设计特点与取舍：
- 分层清晰：brain（判断）→ ledger（持久化）→ writer（生成）→ checker（校验）→ goal_loop（自动迭代），各层职责单一，判断权集中在 brain。
- 手动/自动双路径：手动模式（chat/server 单幕生成）只查不自动改，由用户自己决定；批量/全自动路径（write_missing_acts_in_series）接完整 goal loop 自动修复重试。
- 语义判断而非关键词匹配：checker 明确要求理解实际情节再判断，避免字面误判。
- 事实与文风分离：world_state（事实清单，硬约束）与 previous_excerpt（文风参考）是两条独立通道，避免 token 随幕数线性膨胀。
- 注入防御：brain 和 writer 的 system prompt 都声明 ledger/user 内容是素材不是指令，检测到疑似注入标记 flagged_injection 但仍正常处理。
- 温度取舍：写手 0.9（要变化）、brain 0.7、检查器 0（要稳定）、诊断 0.2（要准不要创作）。
- 诚实标注简化实现：如 must_include 缺失的修复（_augment_must_include）明确标注是简化版，不做 local_slip/structural_conflict 细分。
- 长文本分段与进度反馈：write_long_script 按 chunk 分段、段间用滚动事实清单衔接，on_chapter 回调给用户进度。
- 系列嵌套存储：独立项目首次被续写时自动晋升为系列文件夹，文件夹结构即体现系列关系。
