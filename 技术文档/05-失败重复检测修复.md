# 失败重复检测修复

> 对应 [04-第3步实验记录与发现的问题.md](04-第3步实验记录与发现的问题.md) 第4节记录的缺陷，这里是修复本身。
> 最后更新：2026-08-15

## 1. 问题回顾（一句话）

`agent.py`/`agent_mcp.py`遇到一个动作失败后，只是把报错原样拼回`transcript`，没有任何"这已经是第几次失败了、该换个思路"的提示，实测中 agent 会对着同一个必然失败的路径反复重试到撞上`MAX_STEPS`上限，一次都不会自己换路径。

## 2. 修复思路

不改变"要不要继续、下一步干什么"这个决定权——**依然完全由模型自己判断**，这条边界不动。改的是**喂给模型的信息本身**：在检测到"这一步的动作（action + path）跟上一步完全一样"时，往观察结果里显式加一句提示，把"你已经重复了"这件事挑明说出来，而不是让模型自己去数transcript里有几条一样的报错。

```python
def repeat_notice(action: str, path: str, repeat_count: int) -> str:
    return (
        f"\n\n【系统提示：你已经连续{repeat_count + 1}次执行完全相同的动作"
        f"（{action} {path!r}），都没有找到你需要的东西——不要再重复同一个动作了。"
        f"换一个不同的路径试试，或者调用list_directory路径传空字符串，"
        f"重新看一眼代码库根目录下实际有哪些文件/文件夹，你对路径的假设可能是错的。】"
    )
```

`agent.py`和`agent_mcp.py`的循环里都加了同样的检测逻辑（记录`last_action_key`和`repeat_count`，动作跟上一步相同就计数，不同就清零），从第2次重复开始触发提示——不是等到快撞上限才提示，是一发现"原地打转"的苗头就说。**两个文件共用同一个`repeat_notice`函数**（`agent_mcp.py`直接从`agent.py`导入），不是各写一份，避免以后改一个忘了改另一个。

这个修复思路直接搬自`goal_loop.py`——检查器发现违反后不会让写手带着同样的错误盲目重写，会先诊断原因再给针对性提示；这里是同一个模式的复用：**观察结果本身信息量不够、模型没能自己从原始信息里悟出问题时，需要额外一层"诊断+提示"的加工，不能指望模型总能自己看出该往哪个方向调整。**

## 3. 修复效果验证（真实复现原始失败场景）

拿第3步里那个真实导致连续8次撞上限的问法（`"flask/json/这个子目录下有哪几个.py文件？"`，路径多套了一层`"flask/"`），修复前后对比：

| | 修复前 | 修复后 |
|---|---|---|
| `agent.py`（无MCP） | 连续8次`list_directory("flask/json")`，撞上限，未答出 | 第2步重复后收到提示，第3步主动退回`list_directory("")`看根目录，第4步试对`"json"`，第5步正确作答 |
| `agent_mcp.py`（MCP） | 同上 | 只重复1次就换路径，4步内正确作答，比无MCP版本更快换策略 |

**注意：这次验证用的是原始的、有问题的题目文字（"flask/json/"），不是已经改正确的版本**——这样才能真正证明"agent自己学会了应对路径猜错这种情况"，而不是"因为题目改对了所以侥幸没触发"。这是修复有效性的关键证据，跟单纯"题目改对了所以答对了"是两回事。

## 4. 这个修复解决到什么程度，不要高估

- **只处理"完全相同的动作连续重复"这一种模式**，不处理"绕圈子但没有逐字重复"的情况（比如`list_directory("flask/json")`失败后，试了`list_directory("Flask/Json")`大小写不同，或者在两三个不同的错误路径之间来回切换但没有任何一个连续重复）——这些更隐蔽的"原地打转"目前还是检测不到。
- **阈值（连续2次触发提示）是拍脑袋定的**，没有专门调过——比这更早触发会不会太啰嗦、比这更晚触发会不会浪费步数，都还没有真实数据支撑，需要更多真实案例才能判断这个数字合不合适。
- 这次验证只在一道题上真实复现过，**样本量是1**，跟`checker.py`当年首次验证时的告诫一样：这不代表这个修复在所有"路径猜错"场景下都同样有效，只能说明这一种真实观察到的失败模式已经被解决了。
