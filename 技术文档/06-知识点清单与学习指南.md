## 知识点1：大模型API的基础调用方式

**是什么**：每次跟大模型对话，本质上是发一个HTTP请求，里面包含几个关键部分——`system_prompt`（规定这次对话模型该扮演什么角色、遵守什么规则，全程不变）、`user_content`（这一次具体要处理的内容）、`temperature`（0到1之间，越低答案越稳定重复，越高越有变化）、`json_mode`（要不要强制模型只输出合法JSON，不能有别的废话）。

**今天在哪用到**：`deepseek_client.py`里的`call()`函数就是对这几个参数的封装，`agent.py`每一轮循环都在调用它——`temperature=0.2`（要稳定判断，不要有创作性发挥）、`json_mode=True`（强制它只输出我们规定格式的JSON，不然没法用代码解析它的决定）。

**想深入学看什么**：这个不算新知识，你们从`自动剧本生成机`的`brain.py`/`writer.py`就一直在用同一套（那边`brain.py`温度0.7，`writer.py`温度0.9，读码机这里0.2），本质是同一件事换了参数——不需要额外找资料，已经很熟了。

## 知识点2：读代码这件事，到底以什么形式喂给模型（重点讲）

你反复问到这个，说明之前几次解释都没有完全讲透，这次用一次真实发生过的对话，逐字拆开看。

**核心事实：模型从来没有"看到"整个代码库。它只看到我们喂给它的一段纯文字（`transcript`），这段文字一开始很短，随着每一轮"读了什么文件"不断变长。**

拿第7题真实跑过的过程举例，`transcript`这个变量的内容变化过程是这样的：

**第1轮喂给模型的内容**（一整段文字，就这么多）：
```
<question>为什么write_missing_acts_in_series这个函数要从writer.py挪到goal_loop.py？</question>

（还没有做任何操作。）
```
模型这时候**根本没看到任何代码**，只看到这道题。它能做的只有输出一个JSON，比如：
```json
{"action": "list_directory", "path": ""}
```

**这个JSON被我们的代码（`agent.py`）拿到之后，代码自己去执行了"列出根目录文件"这个动作**，拿到一份文件名列表，把这份列表**原样拼接**进`transcript`，变成第2轮要喂给模型的内容：
```
<question>为什么write_missing_acts_in_series...？</question>

（还没有做任何操作。）

=== 第1步 ===
你的动作：{"action": "list_directory", "path": ""}
观察结果：brain.py
checker.py
checker_include.py
chat.py
goal_loop.py
ledger.py
server.py
writer.py
```

**第2轮，模型看到的就是上面这一整段文字**（比第1轮长了），它看到文件列表里有`goal_loop.py`和`writer.py`，这次输出：
```json
{"action": "read_file", "path": "goal_loop.py"}
```

代码执行这个动作，把`goal_loop.py`**整个文件的原始文本内容**（就是普通文本，不是什么特殊格式）拼进`transcript`，第3轮喂给模型的内容变成"前两轮的全部文字 + goal_loop.py的完整源码"——**这时候模型才第一次真正"看到"代码，看到的方式就是这份源码变成了一大段文字，跟题目文字拼在一起，一起被当作这一轮的输入。**

这个过程重复几轮，`transcript`越滚越长，直到模型觉得信息够了，输出`{"action": "final_answer", "answer": "..."}`，循环结束。

**一句话总结**：读代码 = 把文件的原始文本内容，当普通文字一样拼进发给模型的那段话里，模型用理解任何一段文字的方式去理解它，不存在什么"代码专用的读取通道"。这也是为什么大文件是个真实问题——文件内容会让`transcript`变得很长，长到一定程度就是context engineering要解决的事。

**想深入学看什么**：这个模式有个专门的名字叫**ReAct**（Reasoning + Acting，推理+行动交替进行），是2022年一篇论文提出的概念，现在几乎所有"agent"都是这个模式的变体。想系统了解可以搜"ReAct prompting"，但说实话，你们自己写的`agent.py`已经是一个完整、能跑的ReAct实现，比看论文更直观——**建议先把`agent.py`这73行代码逐行看懂，比找论文看更有效率。**

## 知识点3：评测集（考卷）是干什么用的（重点讲）

**先明确一件事：考卷（`eval_set/*.json`）不是agent运行时会用到的东西，agent运行的时候根本不知道考卷存在。**

考卷是**外部的、事后的质检工具**，运作方式是：

1. 人（出题人）先自己搞懂目标代码库的某个具体事实（比如"MAX_ATTEMPTS等于3"），把"问题"和"正确答案"都写进考卷文件里，这一步**不需要agent参与**。
2. 运行`run_eval.py`，让agent去回答考卷里的每个问题——这一步agent只看到"问题"本身，**看不到考卷里存的标准答案**，靠自己读代码去找答案。
3. agent答完之后，代码把它的答案和考卷里的标准答案**并排存起来**（`step1_结果.json`这类文件），人再拿这两份答案对照看，判断agent答得对不对。

**类比一下**：考卷就是一份"有标准答案的练习题"，agent是"做题的学生"，`run_eval.py`是"监考+收卷"，人是"批卷老师"。agent做题的时候看不到答案，这是考试的基本要求，不然就没有意义了。

**为什么需要这个东西**：如果没有考卷，agent随便说什么答案我们都没法判断对不对——"听起来很有道理"不等于"是对的"。今天第3步能发现"agent失败后不会换策略"这个真实问题，靠的就是有一份写死的标准答案能对照，如果没有考卷，那次失败可能被误认为"这题它就是不知道"，看不出"它其实是在犯同一个错误"这个更深层的问题。

**想深入学看什么**：这个概念在AI工程里叫**evals**（evaluation的缩写，业内基本直接用这个词，不翻译），是目前AI应用工程里一个很受重视的专门方向——怎么系统性地判断一个AI系统靠不靠谱。你们自己的`剧本评测机`项目，本质上做的就是同一件事（只是评测对象是生成的剧本内容，不是agent答题）。想深入可以搜"LLM evals"或者"how to build evals for AI agents"，会有大量最近一两年的实践文章。

## 知识点4：MCP协议

已经在对话里详细讲过（裸JSON报文都实际截图看过），这里只列要点，不重复：

- **是什么**：一套规定"客户端程序"和"服务端程序"之间怎么用JSON消息互相调用工具的标准格式，本质上是JSON-RPC协议的一种具体应用。
- **今天怎么用的**：`mcp_server.py`把`list_directory`/`read_file`两个函数包成符合协议的服务端；`agent_mcp.py`作为客户端，通过这套协议去调用，而不是直接import函数调用。
- **模型在这里面的位置**：模型不直接接触MCP协议，它只是输出普通文字/JSON告诉我们的代码"它想干嘛"，真正发MCP消息的是`agent_mcp.py`这段普通Python代码。
- **想深入学看什么**：官方文档 modelcontextprotocol.io 有协议规范的完整说明；更直观的方式是照着`技术文档/raw_mcp_demo.py`这个手写裸协议的例子自己改改看，比如让它调用`list_directory`而不是`read_file`，观察报文长什么样。

## 知识点5：`async`/`await`（异步编程）

**是什么**：正常写代码，程序执行到一个函数调用会原地等它跑完才能往下走。`async`/`await`允许你写"这一步要等（比如等别的程序通过管道回话），但可以不这么死等"的代码。

**今天为什么用到**：`mcp`这个库内部就是用`async`/`await`写的，我们想用它就得跟着写`async def`/`await`，不是我们主动选择要不要异步，是被这个库的设计逼的。

**老实说**：这次没有真正用上异步的好处（没有真的"同时做几件事"），只是为了能调用`mcp`库不得不这么写。这个知识点**优先级可以放低**——不建议现在专门去系统学"Python异步编程"，等真的遇到一个"需要同时处理很多件事"的场景（比如agent要同时问好几个问题、互不等待），到时候再学会更有动力、更容易理解为什么需要它。

## 知识点6：安全边界设计（路径遍历防护）

**是什么**：`tools.py`里的`_resolve`函数，防止别人（这里是模型）通过类似`"../../别的文件夹"`这种路径写法，跳出规定的目录范围去访问不该访问的文件。这是一类很常见的安全问题，叫**路径遍历攻击（path traversal）**，不止AI agent场景会遇到，任何"根据用户输入去读写文件"的程序都要考虑这个。

**今天怎么处理的**：用`os.path.normpath`把路径标准化（解析掉`..`这类符号），再检查算出来的绝对路径是不是真的落在允许的根目录内部。

**想深入学看什么**：这是通用软件安全的基础知识点之一，不是AI特有的，搜"path traversal vulnerability"能找到大量经典案例（包括真实发生过的安全事故），了解一下这类攻击的常见形态，以后写任何"接受外部输入决定读写哪个文件"的代码都用得上，不局限于agent项目。
